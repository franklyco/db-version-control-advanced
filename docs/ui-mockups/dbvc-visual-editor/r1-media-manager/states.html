R1 Media Manager - state gallery

Every scan, result, and expansion state the R1 read-only release can present. The default view lives in index.html.

Provenance. Cases 1, 2, 3 and 4 have no counterpart in the R1-C fixture, which contains one completed scan. Their progress numbers, timestamps, and error text are illustrative placeholders for layout only and must not be treated as contract values. Cases 5 through 9 are fixture-exact. Case 10 illustrates a request error that returns no row payload, and case 11 illustrates a contract-valid partial page; neither is the default fixture response, which returns every matching row with hasMore: false.

Backend state vs. presentation. Backend evidence is scanning, failed, canceled, complete, and invalidated. The friendly labels below come from a documented adapter, not from a server field. Retry and Cancel are driven strictly by canRetry and canCancel, never inferred from a label. The full mapping is in WIRING-SCHEMATIC.md section 2.1.

1. No current scan

GET /scans/latest returned 404 media_scan_expired_or_invalid, or no usable snapshot. Deliberately not called “No scan yet”: the current contract cannot distinguish a scan that was never created from one that expired or was invalidated, so the copy must not assert either. Only Start/Refresh is offered; there is nothing to continue, cancel, or retry. Illustrative placeholder state.

10. Expansion request unavailable (404, no row payload)

Request state, not a row status. The expansion call returned 404 media_scan_group_unavailable. There is no row object, no counts, and no fields[] - so nothing about the group's fields can be shown. This is the case for a group that was unpublished, deleted, moved out of the published scope, or whose snapshot entry expired. Contrast with case 9, where the group resolved and its fields were returned but the rescan provider failed.

11. Partial page with Load more (illustrative)

Illustrative, not the default fixture response. The canonical fixture returns all six matching rows under limit: 20, so it declares hasMore: false with an empty cursor and index.html omits this control entirely. To demonstrate the paging affordance, this case shows a contract-valid partial first page - the same safe fixture entities under a smaller limit, where the server would legitimately report another cursor page.

12. Focus, motion, and contrast behaviour

Tab through the controls below to see the focus treatment. The ring is 2px solid var(--dbvc-ve-color-focus) at outline-offset: 2px, matching .dbvc-ve-panel__richtext:focus in overlay.css.

Chip focus
Buttons

Reduced motion. The only animation in the component is the row chevron rotation; @media (prefers-reduced-motion: reduce) removes its transition. Forced colours. Every chip re-borders to CanvasText under @media (forced-colors: active) so status stays distinguishable. Colour independence. Field-family chips carry a leading glyph (Featured ACF image Gallery) and every status chip states its status in words.

13. Responsive behaviour

Narrow this window to check both breakpoints on index.html. At ≤1024px the table is retained and the chrome tightens: summary notes and the entity-family sub-label are dropped, and the scan band stacks. At ≤640px each row becomes a card. Column headers move out of the visual flow but stay in the accessibility tree, and every value prints its column name from data-label, so no information is lost. Explicit ARIA roles in the markup preserve table semantics through the display: block transform.
