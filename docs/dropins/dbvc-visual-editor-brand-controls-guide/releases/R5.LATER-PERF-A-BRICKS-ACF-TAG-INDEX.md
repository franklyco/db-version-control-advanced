# R5.later-perf-a — Bricks ACF dynamic-data tag-index shim (options A + B)

**Status:** LANDED 2026-09-17 (E-160, D-082). Default **off**. Live equivalence verified on the reference site; the maintainer enables it in Settings → Visual Editor.
**Parent:** R5.later-perf (TTFB root cause E-159, `qa/R5-LATER-PERF-TTFB-INVESTIGATION.md`).

## What it fixes

Bricks rebuilds its ACF dynamic-data tag registry on every frontend / REST request at `init`. On this schema (49 groups, 3 288 nested sub-fields, 2 700 tags) ≈ 1.5 s of that is a quadratic lookup in `Provider_Acf::get_nested_parent_group_field_data()`. This slice ships the same fix two ways:

- **A — upstream:** `qa/R5-LATER-PERF-TTFB/UPSTREAM-BRICKS-REPORT.md` + `bricks-2.3.8-provider-acf-indexed-lookup.patch` (83-line diff, verified on the live site: 1 621 → 52 ms, registry identical). The maintainer submits it to Bricks.
- **B — DBVC shim:** `addons/visual-editor/src/Performance/Bricks/` — an opt-in, fingerprint-pinned, self-verifying replacement of the provider *instance* so the site gets the gain now and can drop the shim when Bricks lands A.

The other ≈ 2 s (ACF's cold field materialisation) is untouched — see option C in the investigation.

## How B works

| Piece | Role |
|---|---|
| `AcfTagIndex` | Pure index: sub-field key → tag names, name → first-insertion position. `lookup()` returns *the first tag in array order whose current sub-fields carry the key* — the stock scan's exact semantics, validated per hit. `referenceLookup()` is the stock scan, kept as the oracle. |
| `IndexedAcfProvider extends Provider_Acf` | Overrides `register_tag()` with a dispatcher to one verbatim copy per pinned Bricks version (`register_tag_bricks_2_3_8`, `register_tag_bricks_2_3_13`, `register_tag_bricks_2_4_5`; GPL, attributed), each with `indexTag()` after each whole-tag `$this->tags[ $name ] = …;`, and `get_nested_parent_group_field_data()` with the indexed lookup (skipping `is_loop_outer` tags on 2.4.5, as stock does). Private-parent calls go through reflection. Never constructed normally (see below). |
| `ProviderFingerprint` | sha1 of the whitespace-normalised source of six Bricks methods read from the installed theme (`register_tag`, `get_nested_parent_group_field_data`, `get_fields_by_context`, `get_flexible_content_parent_layout_data`, `Base::__construct`, `Providers::register`). `KNOWN` pins `07662227…` = Bricks 2.3.8–2.3.9, `22fd17e9…` = 2.3.13 and `463ec9d1…` = 2.4.5; `REGISTER_TAG_VARIANTS` maps each pin to its vendored copy and `NESTED_LOOKUP_SKIPS_LOOP_OUTER` marks the pins whose nested-group scan skips `is_loop_outer` tags. |
| `AcfTagIndexShim` | Gate + swap + verify + status. |

**Runtime sequence (only when the switch is on):** `after_setup_theme@0` → `arm()`: switch on? Bricks classes present and the private static provider registry accessible? fingerprint known **and** recorded as verified on this site? → hook the swap on Bricks' own registration hook (`bricks/dynamic_data/register_hook`, default `init`) at priority 10000, i.e. after Bricks' `register_providers` (same priority, registered earlier) and before `register_tags` at 10001. `swap()`: the registered `acf` provider must be exactly the stock class with no tags yet and its three constructor filters (`bricks/setup/control_options`, `bricks/query/run`, `bricks/query/loop_object`) at priority 10 — otherwise no-op. Then: create `IndexedAcfProvider` **without running the constructor** (`newInstanceWithoutConstructor` + `adopt('acf', $fingerprint)`, which selects the vendored copy and throws — leaving the stock provider — if none exists, so the base constructor's filters are never duplicated), move the three filters from the stock instance to the new one with the same priorities and accepted-args, and replace `Providers::$providers['acf']`. Nothing else in Bricks is touched; `get_tag_value`, loop queries, builder tag lists all run on the new instance with the identical registry.

**Verification (`verify()`):** builds the registry with a stock provider and with the indexed one and requires `tags` and `loop_tags` to be `===` (keys, order, values). Runs on settings save when the box is ticked (records the fingerprint as verified or as `failed:<fp>`), and on demand. The gate refuses to arm unless the recorded fingerprint equals the current one — so a Bricks update flips the shim off by itself until it is re-derived and re-verified.

**Contexts:** admin (Bricks registers no providers → `no_acf_provider`, no-op), REST/AJAX/frontend/builder (providers registered → swap applies; output identical).

## Safety review

- **No behaviour change by construction:** the only altered method is a search whose result is proven equal to the stock scan (property test replaying 120 000 lookups against the oracle; live `verify()` on 2 700 tags + 183 loop tags: 0 differing records; rendered sample tags identical).
- **Fails closed:** any of — switch off, filter veto, Bricks absent, registry shape changed, fingerprint unknown, not verified, provider already replaced by someone else, tags already registered, filters not where expected, exception during swap — leaves the stock provider in place. `state()` names the reason; the settings help text shows `gate` and verification status.
- **No runtime writes.** The only write is the verification marker on settings save / explicit verify.
- **Kill switch:** untick the box (or `wp option update dbvc_visual_editor_bricks_acf_tag_index_enabled 0`). Effect is immediate on the next request.
- **Not gated on the Visual Editor master switch** — deliberately site-wide (help text says so), because every request pays the cost, not just editor requests.

## Enable + verify (maintainer)

1. Settings → Visual Editor → **Performance — Bricks compatibility (site-wide)** → tick **Index Bricks ACF dynamic-data tags** → Save. The save runs `verify()`; the help text then reads `gate: ready · verification: passed for 07662227…`. If it reads `FAILED` the switch stays on but the shim never arms — report it.
2. Confirm on the front end / REST (any logged-out request): `curl -k -o /dev/null -s -w '%{time_starttransfer}\n' https://dbvc-codexchanges.local/wp-json/` — expect ≈ 4.1 s → ≈ 2.6 s on this site.
3. Anytime: `wp eval 'echo json_encode(\Dbvc\VisualEditor\Performance\Bricks\AcfTagIndexShim::status());'` and `wp eval 'echo json_encode(\Dbvc\VisualEditor\Performance\Bricks\AcfTagIndexShim::verify());'` (read-only unless `verify(true)`).
4. After a Bricks update: `status()` shows `gate: fingerprint_unknown` (unpinned release — the shim is inert) or `gate: not_verified` (pinned release, not yet verified on this site — re-save the settings page to run `verify(true)`).
5. Re-pin a new Bricks release (read-only on the theme):
   1. `php tests/fixtures/bricks-provider-acf/extract.php <themes/bricks> tests/fixtures/bricks-provider-acf/bricks-<version>.php` — verbatim excerpt of every pinned method.
   2. Diff the pinned methods against the previous fixture. If `register_tag()` changed, add a `register_tag_bricks_<version>` copy to `IndexedAcfProvider` (verbatim + the two `// R5.later-perf-a` index lines + the two reflection calls). If only other pinned methods changed, check whether the copy still holds and reuse its variant.
   3. Add the hash to `ProviderFingerprint::KNOWN` + `REGISTER_TAG_VARIANTS` (and `KNOWN_FIELDS_CACHE` if perf-b's four methods moved), and the fixture to `VisualEditorBricksAcfTagIndexParityTest::FIXTURES`.
   4. `vendor/bin/phpunit --filter VisualEditorBricksAcfTagIndexParityTest` — the copy must equal Bricks' source with the documented edits undone, and the registries must be identical tag by tag; `DBVC_BRICKS_THEME_DIRS=<dir>[:<dir>…]` also runs the installed themes.
   5. On a site: `verify(true)` must return `identical`.

## Evidence (2026-09-17, LocalWP, Bricks 2.3.8, PHP 8.4)

- Real boot with the shim forced on in-process (filter + in-memory verified marker, no writes): `state active`, provider `IndexedAcfProvider`, `bricks/query/run` / `control_options` / `loop_object` each carry exactly one ACF callback and it is the indexed instance (no stock leftovers), 2 700 tags, `init` **4 071 → 2 598 ms**, sample tag renders identical to the stock boot.
- Upstream patch applied to a renamed copy of the stock class: 1 621 → 52 ms, identical.
- PHPUnit: `VisualEditorBricksAcfTagIndexTest` 9 tests (index vs oracle property replay, order/overwrite semantics, fingerprint normalisation, gate refusals without Bricks, filter veto/force, verify writes nothing when refused, settings wiring + save path); suite 480 / 3 365. jsdom unchanged.
- `composer agent-docs:check` passes (new filter mapped; four VE hook IDs re-mapped after their byte offsets moved — see resume prompt note).

## Re-pin evidence (2026-11-12, Bricks 2.3.13 + 2.4.5)

- 2.3.8 and 2.3.9 hash to the same perf-a pin (`07662227…`); their six pinned methods are byte-identical. 2.3.13 hashes to `22fd17e9…`: the only change in the pinned methods is a new block at the top of `register_tag()` that registers the resolved sub-fields of **group-display clone fields** (Bricks `#86c50h1ma`); seamless clones still return. That block is ported verbatim into `register_tag_bricks_2_3_13`. (Outside the pinned methods 2.3.12/2.3.13 also changed `Base::get_tag_value`'s `tel` filter and added `Providers::get_provider_for_rendering()`; neither is overridden or relied on by the shim.)
- perf-b's pin `0ca8ed62…` is unchanged on 2.3.13 (`get_fields`, `get_fields_locations`, `required_hooks`, `flush_cache` identical).
- `VisualEditorBricksAcfTagIndexParityTest` (9 tests) runs `tests/fixtures/bricks-provider-acf/parity-harness.php` once per pinned version, in its own PHP process, against verbatim excerpts generated by `extract.php`: fixture hashes = pins; vendored copy = Bricks source once the documented edits are undone; `IndexedAcfProvider` vs stock tag by tag (`tags`/`loop_tags` `===`, same order) over a hand-written schema reaching every `register_tag()` branch (nested groups, duplicates, repeaters, keyed/indexed flexible layouts, group/seamless/empty/nested clones) plus five seeded random schemas (~150–250 tags each); `verify()` → `identical`, gate → `ok`, arm → swap → `active` with the three filters re-pointed and an identical registry; running the other version's copy fails both checks; a one-token edit inside each of the six pinned methods → `fingerprint_unknown`, no swap hooked, nothing persisted, `adopt()` refuses; whitespace-only edits keep the pin. A one-character change to the 2.3.13 copy fails 3 of the tests.
- Same harness against the installed themes (read-only): LocalWP sites on 2.3.8, 2.3.9 and 2.3.13, and a 2.4.5 theme copy — all pinned, copy matches, every schema identical.
- 2.4.5 hashes to `463ec9d1…` (read-only theme copy). Two pinned methods changed: `register_tag()` now also stores an `is_loop_outer` copy of each top-level repeater / flexible-content / loop field in `tags` when the name is free (a third whole-tag assignment — indexed like the others), and `get_nested_parent_group_field_data()` skips `is_loop_outer` tags. Both are ported, the skip keyed to the 2.4.5 pin. `register_providers` / `register_tags` / the static registry are unchanged; the large `providers.php` diff is the render path (`extract_dynamic_data_tags`), which the shim does not touch. perf-b's pin is unchanged on 2.4.5.

## Rollback

Untick the switch (soft, seconds). Hard: delete `addons/visual-editor/src/Performance/Bricks/`, revert the `R5.later-perf-a` hunks in `bootstrap.php` (constant, two `add_option`s, settings group/meta/save, `register()` call, `SETTINGS_VERSION` 8 → 7), the two SETTINGS_VERSION test assertions, and the manifest mapping. The two options may stay.
