# R5.later-perf-c — Brand Control Center server costs: record-pass memo + batch session attach

**Status:** LANDED 2026-09-17 (E-163). No switch — pure removal of repeated work, behaviour-identical by construction and by test.
**Parent:** R5.later-perf audit (E-162, `qa/R5-LATER-PERF-AUDIT-REPORT.md` findings **F2** and **F3**). The audit's F1 (the Vertical provider re-materialising ACF's local field store on every control-center request, ≈ 2.7 s) is **not** in this slice — see §5.

## 1. What changed

| Piece | Before | After |
|---|---|---|
| `ControlRegistry::collectValidRecords()` | Ran on every read: `listControls()`, and `getVisibleRecord()` once **per public id** — each pass calls every provider's `getControls()`, validates, de-duplicates, sorts and DFS-flattens all records (62 ms warm on the reference site's 401 controls; the value-summary batch route paid it N times per request) | Memoised per registry instance (= per request). Invalidated by `registerProvider()` (a provider registered after the first read must show up) and by the new public `resetRecordCache()`. `getVisibleRecord()` answers from a lazily built `publicId → record` index. Per-user visibility (`ControlRecord::isVisibleToCurrentUser()`) is still evaluated on every read — the memo holds provider output, never a capability decision. `getProviderErrors()` now describes the memoised pass until the cache is reset (the two R4-A error tests still hold). |
| `EditableRegistry::addDescriptorToSession()` | One `loadSession(…, true)` (decodes the whole gz+base64+json descriptor blob — 402 ms for 681 descriptors), public-map rebuild, re-encode and one `set_transient()` of the ≈ 0.5 MB payload **per descriptor** | New `addDescriptorsToSession($session_id, EditableDescriptor[]): array<token, bool>` does all of that **once** for any number of descriptors; the single form is now a wrapper over it with unchanged semantics (empty token / excluded descriptor → `false` without touching the others; missing or foreign session → all `false`, nothing written; a later duplicate token wins as it would serially). Profiled as `registry.session.attach_batch` when the performance profiler is on. |
| `ControlCenterOpenController::handle()` | Attached the parent, then each capability-cleared pre-minted leaf (R5.later-y-3), **20 round-trips** for the Vertical Global Palette | Collects the parent and the capability-cleared leaves first (a leaf with no token or the parent's own token is skipped, as before), attaches them in one call, and reports back exactly the descriptors the registry accepted. The parent's own result still gates the 404. |

Nothing else moved: same routes, same payload shapes, same capability checks per descriptor, no new write authority, no new options.

## 3. Safety review

- **Memo scope is one PHP request.** The registry is constructed per request in `Addon::__construct()`; nothing persists across requests, so schema changes are picked up on the next request exactly as before. Within a request the only mutation path that could change provider output (a save that adds/removes a repeater row) does not read the registry afterwards; if a future slice needs that, it calls `resetRecordCache()`.
- **Fail-closed unchanged.** Unknown/malformed public ids, visibility-blocked records, provider exceptions (captured, others kept) behave as before — covered by the existing R3-A/R4-A tests, which pass unmodified.
- **Session attach is all-or-nothing per call only in the sense that one write carries every accepted descriptor**; per-descriptor refusals (excluded, token-less) are still individual and never block the others, matching the serial behaviour the open controller relied on.

## 4. Rollback

Revert the three hunks (`ControlRegistry` memo + index, `EditableRegistry::addDescriptorsToSession` + wrapper, the open controller's collect-then-attach block) and the six tests. No data migration — the session payload format is unchanged.

## 5. Left open (from the audit)

- **F1 — ACF store re-materialisation (≈ 2.7 s on every control-center request):** a fingerprinted cache of the Vertical provider's *mapped* control records (DBVC seam in `ControlRegistry`/provider contract + Vertical participation, cross-repo like perf-b's WS Form bridge). Biggest remaining server win (S3 3.56 s → ≈ 0.9 s, S6 → ≈ 1.2 s, every value-summary batch −2.7 s). Proposed as the next slice.
- **F4/F6 — client (perf-d):** value-summary flush window + in-flight cap + abort on close; hovered descriptor before viewport prefetch + pump back-off.
- **F5 — session blob size** (0.5 MB, 402 ms decode) only if the residual still shows after F1.
