# M4 preparation, then separately bounded M5

Begin with M4 only. Reconcile actual supported DBVC/Bricks prepare/apply/backup services and read the release/recovery design. Build one immutable release manifest and exact target prepare receipt for a selected supported domain. Resolve portable identities and dependencies, preserve unrelated collection entries, and bind expected state to all storage containers touched. Preparation must leave content unchanged.

Record unresolved dependency coverage and concurrency gaps. A DBVC-only lock cannot protect against an external Bricks editor writer. Do not claim safe automatic apply from a fingerprint check followed by unconditional option update.

After M4 is verified and a disposable target/write scope is established, M5 may implement one guarded round trip using existing engines. Bind approval to immutable manifest/target/state/policy/profile versions, persist operation receipts, verify stored state and rendering separately, recover lost responses by operation status, and test compensation plus rollback-after-later-edit conflicts. No fleet-wide auto-deployment or broad force option belongs in this slice.
