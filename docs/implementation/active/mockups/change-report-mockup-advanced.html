Policy

Same fields as today; Report only hides the apply-side switches because nothing applies.
iReport only never approves a release and never writes to butler-local. The LocalWP apply gate stays off. To push a change for real, select items in a report and Create release; that goes through prepare → approve → apply like any other release.
The hub scheduler runs reports in the same tick as parity. Under plain WP-Cron the notification can lag one tick.
A domain only reports when both sites observe it. Opt-in lists live on each site's Connected Environments settings.
Larger deltas span several cycles; the report shows "n cycles remaining" until complete.

Trade-off for review question (a)

Read-only (recommended for CR-3c)

One new machine-REST read (GET /reports?target=me, enrolled principal). No connector-originated writes to hub governance state — keeps the "connectors only observe and poll" invariant. Decisions happen on the hub; the LocalWP operator opens the hub in another tab.

With decisions

Adds a machine-REST write from an enrolled site into approver state. Convenient, but it means a connector's application password can resolve review items — a new trust edge that roles (7b) did not anticipate. If chosen, decisions from a connector are recorded with decided_by=env:butler-local.
